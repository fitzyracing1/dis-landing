● lit  ·  ○ dark

DIS

A self-hostable status bot. It watches your sites and marks each one lit (up and healthy) or dark (down, erroring or too slow).

View on GitHub Quick start

Node 18+ · zero dependencies · MIT · no tracking, ever

● Lit / dark status

HTTP(S), TCP and DNS checks from one status.config.json. Each check can set an expected status code, a maximum latency and a keyword the page must contain. The default interval is 60 s.

DIS alerts only when a light changes (two failures in a row before it goes dark). Alerts can go to Discord, Slack or any JSON webhook, and lights can be mirrored to light-report.

A tiny status page and /status.json show the state, uptime and last check time. State survives restarts.

● On-demand /check API

Other bots can ask whether a URL is lit right now:

POST /check
{"url":"https://example.com","expect":200,"maxMs":3000}
→ {"state":"lit","status":200,"ms":231,"detail":"HTTP 200 in 231ms"}

It's off by default. It needs an API key or an explicit public switch, and it has per-IP rate limits and SSRF protection: private, loopback and metadata addresses are blocked after DNS lookup and on every redirect. There's also a CLI: dis check <url>.

● Discovery of new bots

DIS can optionally find newly published bots through official APIs: GitHub topics, npm, PyPI, the MCP registry, and top.gg with a token. Bot owners can also self-register by proving ownership with /.well-known/dis.txt.

It only checks the one URL each bot published itself, follows robots.txt, waits at least 5 minutes between checks, caps the number of targets and sends an honest User-Agent. No scanning, no crawling.

Quick start

1 · Try it with npx (no install)

echo '{"targets":[{"name":"site","url":"https://example.com"}]}' > status.config.json
npx -y github:fitzyracing1/DIS once        # exit 0 = all lit, 1 = something dark
npx -y github:fitzyracing1/DIS serve       # status page on http://localhost:8080
npx -y github:fitzyracing1/DIS check https://example.com

2 · Or clone it

git clone https://github.com/fitzyracing1/DIS.git && cd DIS
node bin/dis.mjs once
node bin/dis.mjs serve
npm test

3 · Configure

{
  "title": "My status",
  "defaults": { "intervalSeconds": 60, "maxLatencyMs": 5000, "failThreshold": 2 },
  "targets": [
    { "name": "site", "type": "http", "url": "https://example.com", "expectStatus": 200, "keyword": "Example" },
    { "name": "db",   "type": "tcp",  "host": "db.example.com", "port": 5432 },
    { "name": "dns",  "type": "dns",  "host": "example.com" }
  ],
  "alerts": [{ "type": "discord", "url": "${DISCORD_WEBHOOK_URL}" }]
}

${VAR} is filled in from the environment. An alert whose URL comes out empty is switched off.

4 · Deploy

Docker

docker build -t dis .
docker run -d -p 8080:8080 \
  -v dis-data:/data dis

Railway

Create a project from the repo. It uses the included Dockerfile and railway.json, reads PORT, and health-checks /healthz. Add a volume at /data.

GitHub Actions cron

No server needed. The included status.yml runs dis once every 10 minutes, and the job goes red when anything is dark. State is carried between runs.
